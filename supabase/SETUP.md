# Подключение каталога и админ-панели

## 1. Создать Supabase-проект

Создайте проект Supabase и дождитесь, пока база данных станет доступна. В проекте откройте **SQL Editor**, вставьте содержимое [`schema.sql`](./schema.sql) и выполните запрос. Таблица `public.store_products` хранит товар в JSONB, статус наличия, порядок показа и дату обновления. Для таблицы включён RLS; публичного доступа к таблице нет.

## 2. Добавить переменные окружения

В **Project Settings → API Keys** скопируйте:

- Project URL → `SUPABASE_URL`;
- Secret key → `SUPABASE_SECRET_KEY`.

Добавьте `ADMIN_PASSWORD` — придумайте длинный уникальный пароль (лучше не менее 16 символов). На странице `/admin` будет только поле пароля; отдельный пользователь Supabase Auth и `ADMIN_EMAIL` не нужны. Этот пароль также подписывает короткоживущую сессию админки.

`SUPABASE_SECRET_KEY` имеет полный серверный доступ и обходит RLS, поэтому храните его только в переменных окружения сервера и никогда не добавляйте префикс `NEXT_PUBLIC_`.

### Vercel

В Vercel откройте **Project → Settings → Environment Variables** и создайте три переменные: `SUPABASE_URL`, `SUPABASE_SECRET_KEY` и `ADMIN_PASSWORD`. Для Production выберите Production; для проверки на Preview добавьте переменные и в Preview. После добавления или изменения значений создайте новый deployment. Используйте отдельные Preview-значения, если тестовый сайт должен быть подключён к отдельному Supabase-проекту.

### Локальный запуск

Скопируйте `.env.example` в `.env.local` и заполните значениями своего проекта. Не коммитьте `.env.local` и не отправляйте секретный ключ в браузер.

## 3. Импортировать текущие товары

После настройки переменных и публикации откройте `/admin`, войдите под созданной учётной записью, затем нажмите **«Импортировать текущий каталог»**. Импорт доступен только когда таблица пуста и не перезаписывает данные. До импорта магазин использует текущий каталог из исходного кода.

Если каталог уже импортирован, для применения обновлённого описания набора «Диффузор + свеча» выполните [`update-diffuser-candle-set-diamond.sql`](./update-diffuser-candle-set-diamond.sql) в SQL Editor Supabase. Запрос меняет только товар `diffuser-candle-set`.

Чтобы удалить устаревшее краткое описание диффузора 50 мл из уже импортированного каталога, выполните [`remove-diffuser-short-description.sql`](./remove-diffuser-short-description.sql) в SQL Editor Supabase. Скрипт удаляет только поле с точным совпадением этого текста.

Чтобы убрать краткое описание картонного ароматизатора из уже импортированного каталога, выполните [`remove-car-card-short-description.sql`](./remove-car-card-short-description.sql) в SQL Editor Supabase. Скрипт меняет только товар `car-card` и только при точном совпадении текста.

Чтобы обновить название, описание и инструкции микрофибровой тряпки в уже импортированном каталоге, выполните [`update-car-cloth-microfiber.sql`](./update-car-cloth-microfiber.sql) в SQL Editor Supabase. Скрипт меняет только товар `car-cloth`.

## 4. Управление каталогом

В `/admin` можно менять название, категорию, подпись карточки, цену, изображение, описание, объём, аромат, состав и инструкцию; создавать товары; переключать наличие. Если снять товар с сайта, он будет исключён из каталога и его страницы станут недоступны. Если вернуть наличие — товар снова появится.

Для изображения укажите путь к файлу из папки `public` (например, `/shop-product.png`) или публичную HTTPS-ссылку. Файл, добавленный в `public`, всё ещё нужно включить в deployment; панель не загружает изображения в хранилище.

## 5. Управление услугами

Выполните [`services.sql`](./services.sql) в SQL Editor Supabase. Скрипт создаёт таблицу процедур и добавляет все текущие услуги сайта. После этого в админке откройте `/admin/services`: там можно добавлять, редактировать, скрывать и удалять процедуры. Изменения автоматически отображаются на публичной странице `/services`.

## 6. Оформление заказа через Montonio

Перед включением checkout запустите [`store-orders.sql`](./store-orders.sql) в Supabase SQL Editor. Затем добавьте `MONTONIO_ACCESS_KEY`, `MONTONIO_SECRET_KEY`, `MONTONIO_SANDBOX` и публичный HTTPS-адрес сайта в переменные окружения приложения. Для локальной разработки Montonio должен иметь доступный публичный URL для уведомлений; используйте тестовый домен/туннель и `NEXT_PUBLIC_SITE_URL`. Никогда не публикуйте ключи в клиентском коде и не используйте реальные платежи в тестовой среде.
